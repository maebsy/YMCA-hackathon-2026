# 핵심 경쟁사 비교: 권한 · 로컬 검사 · 알림

기준일 2026-10-31. [`competitors.md`](competitors.md)의 핵심 경쟁사 4곳과 우리 서비스를 세 측면에서 비교합니다.
우리 서비스는 **[`system-flow.md`](system-flow.md)의 설계 기준**입니다(현재 구현 상태가 아님). 경쟁사는 공개 자료로 확인한 범위만 적었고, 확인하지 못한 항목은 그렇게 표시했습니다.

## 우리 설계 요약

- **권한**: 기본은 GitHub App(읽기 전용), GitHub 없이 쓰는 CLI 업로드. 확장 후보는 CI(GitHub Actions에서 CLI 실행)와 MCP 모드
- **검사**: 우리 서버의 임시 폴더에서 검사한 뒤 소스는 삭제하고 결과와 의존성 목록만 보관. 해석은 자체 GPU LLM(Red–Blue)
- **알림**: 스케줄러가 매일 새 CVE와 대조해 이메일 알림·재알림. 72시간 타이머, 사고 의심 시 24h(침해사고)·72h(개인정보 유출) 신고서 작성 지원

## 1. 권한: 무엇을 연결하고, 남의 것을 검사할 수 있는가

| | 연결 방식 | 소유·권한 확인 |
|---|---|---|
| Vibe App Scanner | 배포 URL만 입력 | 공식 페이지에서 확인 못 함 |
| Aikido | Git 연동 + 로컬 스캐너 | 저장소 연동이 곧 소유 증명 |
| 라온 PTaaS | 계약 후 화이트해커가 진단 | 계약으로 범위 합의 |
| AI스페라 + KISA 무상 점검 | URL만 입력, 설치 없음 | 선정 절차가 있으나 방식은 비공개 |
| **우리 (설계)** | **GitHub App 읽기 전용 기본** + CLI 업로드 | GitHub App 설치가 소유 증명. **CLI 업로드 경로에는 확인 수단이 없음** |

**판단: Aikido와 대등, URL형 서비스보다 우세.** 읽기 전용이라 권한이 최소이고 비공개 저장소도 받을 수 있습니다. 다만 URL만 넣는 서비스보다 진입 장벽이 높고, CLI 경로가 소유 확인의 빈틈입니다.

## 2. 로컬 검사: 코드가 밖으로 나가는가

| | 방식 |
|---|---|
| Aikido | 로컬 스캐너가 사용자 PC·CI에서 실행되고 코드를 Aikido에 보내지 않음 (Linux·Mac·Windows, CI 8종) |
| Vibe App Scanner | URL 검사라 해당 없음. 결과를 마크다운으로 내보내 AI 코딩툴에 붙여 넣는 방식 |
| 라온 PTaaS · AI스페라 | 해당 없음 (사람 진단 / 외부 점검) |
| **우리 (설계)** | **로컬 검사 없음.** CLI도 소스를 우리 서버로 업로드. 대신 **검사 후 소스 삭제**, **자체 GPU LLM이라 외부 AI 회사로 코드가 나가지 않음**. CI 실행은 확장 후보 |

**판단: Aikido 대비 열세, 나머지 대비 우세.** "외부 AI 미사용·검사 후 삭제"는 강점이지만, "코드를 아예 보내지 않는" 선택지는 설계에 없습니다.

## 3. 알림

| | 방식 |
|---|---|
| Aikido | Slack 즉시 알림(심각도 필터), 주간 요약, **SLA 기한 임박·초과 알림** |
| Vibe App Scanner | Pro($49/월)에 주간 모니터링. 다른 알림 채널은 확인 못 함 |
| 라온 PTaaS | 보고서 중심, 알림 방식은 공개되지 않음 |
| AI스페라 + KISA 무상 점검 | 일회성 이메일 리포트 |
| **우리 (설계)** | **매일 CVE 대조 → 이메일 알림·재알림**, 72시간 타이머, 사고 의심 시 **24h·72h 신고서 지원**, 수정 지시를 MCP로 AI 코딩툴에 전달 |

**판단: 우세.** 다만 Aikido의 SLA 알림이 72시간 타이머와 개념이 겹칩니다. 우리만의 것은 **법정 신고 기한까지 이어지는 알림**과 **비개발자용 설명**입니다. 채널이 이메일뿐이라 비개발자에게 닿는 힘은 약할 수 있습니다.

## 종합

| 측면 | 판단 | 핵심 근거 |
|---|---|---|
| 권한 | 대등~우세 | 읽기 전용 GitHub App, 비공개 저장소 지원. CLI 경로는 소유 확인 빈틈 |
| 로컬 검사 | 부분 열세 | 외부 AI 미사용·검사 후 삭제는 강점. 코드를 보내지 않는 선택지 없음 |
| 알림 | 우세 | 매일 대조 + 72시간 + 법정 신고 기한. 채널은 이메일뿐 |

## 설계에 추가·삭제할 선택지

### 추가 추천

1. **CLI 경로에 소유 확인 추가**: 저장소 확인 파일이나 사이트 DNS·파일 인증을 통과해야 결과(특히 공격 시나리오)를 보여 줍니다. GitHub App과 같은 수준의 권한 보장이 됩니다.
2. **"결과만 업로드" 모드**: CLI가 로컬에서 보안엔진을 돌리고 마스킹된 결과와 의존성 목록만 올립니다. "결과와 의존성 목록만 남김" 원칙을 한 단계 더 밀고, Aikido 로컬 스캐너에 대응합니다. 확장 후보였던 CI 실행도 이 모드로 자연스럽게 해결됩니다.
3. **알림에 신고 기한 연동**: 72시간 타이머 알림(예: 24·48·66시간)에 더해, 사고 의심 시 "침해사고 신고까지 N시간 / 개인정보 유출 신고까지 N시간"을 알립니다. Aikido SLA 알림과 확실히 갈라지는 지점입니다.
4. **카카오 알림톡 채널**: 비개발자 중소기업에게 이메일보다 도달률이 높습니다. 비즈니스 채널 등록이 필요해 후속 작업입니다.
5. **URL 빠른 점검 (선택)**: 저장소 연결 전에 배포 URL로 비침투 점검(보안 헤더, 노출된 `.env`, 공개 DB 설정)을 해 진입 장벽을 낮춥니다. 이 역시 소유 확인이 전제입니다.

### 삭제·축소 추천

- **CLI "소스 업로드" 축소**: 추가 2번(결과만 업로드)으로 바꾸면 남의 소스를 받을 일 자체가 줄어 보관·유출 책임이 함께 줄어듭니다.
- **"매일 지속 검사"를 "매일 CVE 대조"로 명확히**: 설계 문구가 "이후 매일 지속 검사"와 "매일 새 CVE 대조"로 섞여 있습니다. 저장한 의존성 목록만 대조하는 쪽으로 정하면 소스 재수집이 필요 없습니다.
- **MCP 모드는 후순위**: 비개발자 타깃에서는 복사·이메일이 더 중요합니다. 이미 구현된 MCP는 유지하되 확장 우선순위는 낮춥니다.
- **Slack은 추가하지 않음**: 개발자 채널이고 Aikido의 강점 영역입니다.
