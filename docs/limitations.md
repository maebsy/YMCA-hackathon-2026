# 현재 지원 범위와 제한

72hours는 **공개 GitHub 저장소 검사 → 기본 설명·로컬 LLM 해석 → 웹 또는 MCP로 수정 지시 전달 → push 후 재검사 → 리포트**를 제공합니다. 이 문서는 현재 구현의 범위와 운영 조건만 정리합니다. 전체 흐름은 [system-flow.md](system-flow.md)를 참고하세요.

## 기능별 범위

| 영역 | 구현된 범위 | 사용 시 확인할 점 |
|---|---|---|
| 검사 | 공개 저장소 clone, 코드·의존성·비밀키·설정 검사, 신규/지속/해결/확인 불가 비교 | 운영자의 허용 소유자 목록으로 대상을 제한할 수 있음. 스캐너 실패는 안전·해결로 판정하지 않음 |
| 설명·수정 안내 | 규칙 기반 기본 설명, GPU Red·Blue 해석, OS별 명령 템플릿 | AI 해석은 선택 항목에 수행. 모델 검토와 실제 공격 실행은 별개 |
| 전달·재검사 | 웹과 원격 서비스 MCP, 수정 지시 전달, 게시된 기본 브랜치 재검사 | MCP가 사용자 PC를 직접 수정하지 않음. 수정은 사용자 에이전트의 권한과 승인에 따름 |
| 실행 검증 | 데모 과녁의 기준 수정본·AI 수정본 모드 | 현재 공개 API는 데모 전용. 임의 사용자 저장소 실행 서비스는 아님 |
| 기록 | 검사 응답 DB 저장, 선택적 PostgreSQL 정규화 저장·인증 비동기 LLM 모드 | 기본 데모의 LLM·실검증 메모리 결과와 영구 작업 기록을 구분해야 함 |
| 문서 | 점검 리포트, 사용자 확인 기반 사고 신고·통지 초안 | 자동 신고·자동 알림 없음. 신고 초안은 사용자가 보관·확인·제출 |
| 배포 | 일반 서버의 웹·API·MCP 배포 구성, 고정 공개 주소 설정, main CI 기반 자동배포 | 인프라 최초 설정과 운영 환경은 별도. 무중단·다중 인스턴스 운영을 보장하지 않음 |

근거: [보안엔진](../security_engine/README.md), [LLM](llm.md), [MCP](../integrations/mcp-handoff/DISTRIBUTION.md), [실검증](verify.md), [저장 계약](scan-persistence.md), [선택적 비동기 모드](async-llm.md), [자동배포](../deploy/general-server/auto-deploy/README.md).

## 접근과 실행 환경

- 공개 저장소 검사에서 운영자의 소유자 허용 목록은 호출자의 저장소 소유권을 증명하지 않습니다.
- Supabase 인증을 사용하는 선택적 모드와 공개 데모의 접근 방식은 다릅니다. 인증 코드의 존재만으로 모든 공개 경로의 사용자 격리를 보장하지 않습니다([인증·저장 모드](db-erd.md)).
- clone·스캐너 작업은 백엔드 환경에서 실행합니다. 데모 공격 실행용 Docker 격리가 검사 파이프라인 전체에 적용되는 것은 아닙니다.
- 서버의 동시 실행·대기 한도는 자원 보호용이며 사용자별 할당량과 다릅니다. GPU가 바쁘거나 사용할 수 없으면 AI 해석이 늦어지거나 실패해도 엔진 결과와 기본 설명은 유지합니다.

## 기록과 배포

- 검사 결과의 DB 저장과 LLM·실검증 작업의 저장 방식은 다릅니다. 기본 데모의 메모리 작업·결과는 재시작 시 사라질 수 있습니다. 선택적 비동기 worker의 적용 조건은 [async-llm.md](async-llm.md)를 따릅니다.
- 신고 화면의 입력·편집 상태는 브라우저 컴포넌트 메모리에 있습니다. 보관할 초안은 내려받아야 합니다([리포트](reports.md)).
- 자동배포는 진행 중 작업과 변경 범위에 따라 보류할 수 있습니다. MCP 의존성 변경·DB 변경 등 수동 확인 조건과 복구 절차는 [자동배포 안내](../deploy/general-server/auto-deploy/README.md)를 따릅니다.

## 결과를 해석하는 기준

- 검사 0건·재검사 완료는 해당 커밋과 검사 범위의 결과이며 서비스 전체의 안전을 보장하지 않습니다. 실행하지 못한 스캐너·확인 불가 항목을 함께 확인합니다.
- Red의 모델 검토, 실행 검증의 공격 재현·차단 결과, 실제 서비스 전체의 보안성은 서로 다른 근거입니다.
- 테스트·CI·검증 시나리오의 통과율을 실제 서비스의 탐지율·오탐률로 바꾸어 소개하지 않습니다. 공개 저장소 실행 결과만으로도 정답 데이터가 있는 정확도 평가를 대신할 수 없습니다.
- 외부 스캐너의 규칙과 취약점 데이터에 따라 탐지 범위가 달라집니다. 의존성의 수정 버전 안내는 애플리케이션에 패치를 적용하고 동작을 검증했다는 뜻이 아닙니다.
- 취약점 발견은 침해·개인정보 유출의 확정 증거가 아닙니다. 신고 문서는 사용자가 확인한 사고 사실로 작성하는 초안이며 자동 제출하지 않습니다.
