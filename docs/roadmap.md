# 추후 개발 예정 (해커톤 이후)

해커톤 MVP는 **한 번의 흐름이 실제로 끝까지 도는 것**에 집중했습니다:
GitHub 주소 입력 → 보안엔진 검사(`/api/scans`) → GPU Red–Blue 해석(`/api/llm/explain`) → 대시보드 → 수정 후 재검사 → 점검·완료 리포트(`/api/reports/plain`).

아래는 실제 서비스로 운영하기 전에 하나씩 추가할 항목입니다. 위에서부터 중요한 순서입니다.

## 1. 공개 운영 전에 꼭 필요한 것

| 항목 | 지금(MVP) | 추가할 것 |
|---|---|---|
| 소유권 확인 | 공개 저장소 검사는 운영자의 허용 소유자 목록으로 제한 가능(사용자 소유권 확인 아님). 사용자 저장소 실검증은 로그인·소유권 확인 뒤에 켬([현재 범위](verify.md)) | GitHub App(읽기 전용) 연결로 **본인 저장소만** 검사. 남의 사이트 약점 목록을 뽑는 도구가 되지 않게 |
| 검사 서버 격리 | clone·스캐너는 백엔드 프로세스에서 코드를 읽기만 함. 실검증 실행에는 Docker 격리가 구현돼 있고 현재 API는 데모만 허용([격리 근거](verify.md)) | 검사 전용 컨테이너, 디스크·메모리·시간 제한, 네트워크 제한 |
| 남용 방지 | 동시 검사 2건 제한(서버 메모리) | 로그인 사용자만, 사용자별 하루 검사 횟수 제한 |
| 책임 범위 표시 | 리포트에 "검사하지 못한 영역", LLM "수동 확인" 표시 | 이용약관·면책 문구, "0건 = 안전 아님" 안내 강화. 법률 검토(정보통신망법·개인정보) |

## 2. 안정성

| 항목 | 지금(MVP) | 추가할 것 |
|---|---|---|
| 결과 저장 | DB에 전체 결과 저장, 재시작 후 job 조회 유지. PostgreSQL은 scan·tool_run·finding 저장([적용 절차](scan-persistence.md)) | 프로젝트별 재검사 이력·72시간 타이머를 서버에서 관리 |
| 작업 처리 | 서버 안 백그라운드 작업 + 3초 간격 상태 조회 | 별도 작업자(worker)·작업 큐, 서버 재시작에도 이어서 처리 (#32 LLM 작업과 같은 구조) |
| 배포 | 일반 서버(systemd·Caddy), Cloudflare 임시 주소 | 고정 도메인 HTTPS, 장애 알림, Docker 이미지에 엔진·스캐너 포함(지금 Compose 백엔드 이미지에는 없음) |

## 3. 기능 확장

- **매일 지키기**: 매일 새 CVE와 의존성 대조하는 스케줄러, 이메일 알림·재알림 (지금은 재검사 버튼으로 수동)
- **비공개 저장소**: GitHub App 권한으로 clone, 토큰 안전 보관
- **보안엔진 추가 검사**: 과거 커밋 속 비밀키(Gitleaks git 기록 검사), 웹셸 탐지, 같은 줄 여러 규칙 결과 합치기
- **연결 방식**: CLI 업로드(GitHub 없이), CI(GitHub Actions)에서 실행
- **GPU 비용 줄이기**: 엔진 결과는 항상 보여 주고, LLM 해석은 요청할 때만·캐시 재사용
- **요금제**: 취약점 패치 구독 모델 검토

## 4. 해커톤에서 발표로 대신하는 것

GPU 효과 증명(스캐너 원문 · GPU 없는 LLM · GPU LLM · Red–Blue 비교)은 해커톤 필수 항목으로 별도 진행합니다.
