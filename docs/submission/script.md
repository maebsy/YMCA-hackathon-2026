# 발표 대본 (3분)과 예상 질문

발표 시간이 정해지면 길이를 맞춥니다. 아래는 3분 기준이고, 말하는 속도는 1분에 300자 안팎으로 잡았습니다. `[ ]` 안은 실험·실측 후 채울 값입니다. [fact-check.md](fact-check.md)에서 ❌인 내용은 말하지 않습니다.

## 대본

**1장 표지 (10초)**
안녕하세요, 팀 YMCA입니다. 저희는 AI로 만든 사이트의 보안 문제를 쉬운 말로 알려 주고, AI 코딩툴로 고치게 하는 서비스, 72hours를 만들었습니다.

**2장 문제 (20초)**
이제는 코딩을 몰라도 AI로 사이트를 만듭니다. 그런데 만드는 속도를 보안이 따라가지 못합니다. [확인한 통계 1~2개와 출처]

**3장 고객 (20초)**
AI로 예약 페이지를 만든 사장님이 보안 경고를 받았다고 해 보겠습니다. 경고에는 규칙 이름과 CVE 번호만 있습니다. 사장님은 무엇이 위험한지도, 무엇을 해야 하는지도 모릅니다. 기존 도구는 개발자를 위해 만들어졌기 때문입니다.

**4장 해법 (15초)**
72hours는 네 단계로 끝까지 갑니다. 찾고, 쉽게 설명하고, AI 코딩툴로 고치게 하고, 재검사로 정말 고쳐졌는지 확인합니다.

**5장 시연 ① (30초)**
GitHub 주소 하나를 넣습니다. 스캐너 세 개와 저희가 만든 규칙 21개가 코드를 검사합니다. 결과는 "지금 바로 고치세요", "이번 주 안에 고치세요"처럼 우선순위로 나옵니다. 우선순위는 미국 CISA의 SSVC 결정표로 코드가 판정하고, 설명은 GPU 서버의 LLM이 사장님 말로 씁니다.

**6장 시연 ② (30초)**
이제 사장님이 쓰는 AI 코딩툴에서 "72hours 결과대로 고쳐 줘"라고 하면, MCP로 검증된 수정 지시를 받아 고칩니다. 다시 검사하면 "해결됨"으로 바뀌고 완료 리포트가 나옵니다. AI가 경고를 주석으로 숨기거나 잠금 파일을 지워 버리는 꼼수도 그대로 잡아냅니다.

**7장 기술 (20초)**
멘토님 조언대로 탐지와 해석을 나눴습니다. 탐지는 검증된 스캐너가, 위험도 판정은 코드가, 설명은 L4 GPU에서 돌리는 Qwen 27B 모델이 맡습니다. Blue가 설명을 쓰면 Red가 공격자 눈으로 검증합니다. 사용자 코드는 외부 AI로 보내지 않습니다.

**8장 GPU 효과 (20초)**
GPU가 정말 도움이 되는지 쟀습니다. 같은 취약점 [N]건을 스캐너 원문, GPU 없는 설명, GPU LLM, Red–Blue로 각각 안내했을 때, AI 코딩툴로 고쳐서 재검사를 통과한 비율이 [A]%에서 [D]%가 됐습니다.

**9장 차별점 (10초)**
개발자용 도구가 놓친 비개발자를, 찾기부터 완료 확인까지 데려가는 것이 저희의 차이입니다.

**10장 다음 단계 (15초)**
다음은 본인 저장소만 안전하게 연결하는 GitHub App, 매일 새 취약점 알림, 그리고 사고가 났을 때 72시간 안에 신고까지 돕는 기능입니다. 감사합니다.

## 예상 질문과 답

| 질문 | 답의 뼈대 | 근거 |
|---|---|---|
| Snyk·Dependabot·Aikido와 뭐가 다른가요? | 그 도구들은 개발자용입니다. 저희는 비개발자에게 우선순위와 쉬운 설명을 주고, AI 코딩툴에 넘길 수정 지시와 재검사까지 이어 줍니다 | [competitors.md](../competitors.md) |
| 남의 저장소를 검사해서 공격에 쓰면요? | 지금은 허용한 소유자의 저장소만 검사합니다(#69 머지 시). 다음 단계는 GitHub App 연결로 본인 저장소만 검사하는 것입니다 | [roadmap.md](../roadmap.md) 1장 |
| LLM이 틀린 수정을 알려 주면요? | 판정은 코드, 명령은 템플릿이 정하고 LLM은 설명만 씁니다. Red가 검증하고, 통과 못 하면 "수동 확인 필요"로 표시합니다. 마지막으로 재검사가 실제 해결 여부를 확인합니다 | [llm.md](../llm.md) |
| 왜 외부 API가 아니라 로컬 GPU인가요? | 사용자 코드를 외부 AI로 보내지 않기 위해서입니다. 효과는 8장 실험으로 확인했습니다 | [gpu-evaluation.md](gpu-evaluation.md) |
| AI가 경고만 숨기면 해결로 나오지 않나요? | 엔진은 무시 설정과 숨김 주석을 무시하고 검사하며, 숨기려 한 흔적을 따로 표시합니다 | `security_engine/suppression.py`, README "꼼수 표시" |
| 오탐은요? | 결과마다 파일·줄 근거를 보여 주고, 공개해도 되는 키·외부 라이브러리 코드는 숨기지 않되 낮은 우선순위로 내립니다 | security_engine README `flags` |
| 검사 시간은 얼마나 걸리나요? | [검사·해석 실측값]과 그동안 화면에서 무엇을 보여 주는지 | 시연 저장소 실측 |
| 신고서를 잘못 쓰면 책임은요? | 초안 작성 지원입니다. 빈 칸은 지어내지 않고 "제출 전에 채울 칸"으로 보여 주며, 최종 판단과 제출은 사업자가 합니다 | [reports.md](../reports.md) |
| 비공개 저장소는요? | 지금은 공개 저장소만입니다. GitHub App 권한으로 확장할 계획입니다 | roadmap 3장 |
| 돈은 어떻게 버나요? | 가격은 아직 정하지 않았습니다. 구독형을 검토하고 있습니다 | roadmap 3장 "요금제" (**숫자를 지어 말하지 않기**) |
| 왜 72시간인가요? | 개인정보 유출을 알게 되면 72시간 안에 통지·신고해야 합니다. 저희는 발견부터 해결 확인까지를 그 안에 끝내는 것을 목표로 합니다 | 기획안 7장, [reports.md](../reports.md) |
